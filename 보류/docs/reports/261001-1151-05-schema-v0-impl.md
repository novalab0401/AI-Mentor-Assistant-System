# 261001-1151 공통 스키마 v0 구현

- 관련 TODO: schema-v0
- 변경 범위: packages/core 신설, 루트 uv 워크스페이스, 02-specs, 05-coding-rules

## 요약
열린 결정 3건을 확정하고 `packages/core`에 pydantic v2 스키마와 테스트(28개)를 만들었다.
Python 3.13, 3.14에서 모두 통과했다. 지도안 세부 필드, 검토자 기록, 모델 정보는 v0에서 제외했다.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| `undetermined`일 때만 `evidence`를 비울 수 있고 `reason` 필수 | 근거 없는 "판단 불가"는 지어낸 사실이 아니라 못 찾았다는 보고. 사유로 사람이 검토. 02 하네스 규칙의 "판단 불가 허용"과 "근거 최소 1개"가 충돌하던 것을 해소 | 항상 근거 요구 / 사유 없이 허용 |
| "관찰되지 않음"은 별도 상태가 아니라 루브릭 최저 수준 판정, "해당 없음"은 결과가 아니라 루브릭 메타데이터(항목별 적용 세션 유형) | 판단 불가만 시스템 한계에서 나오는 상태. 나머지는 루브릭에서 미리 알 수 있음 | 세 상태를 결과 값으로 |
| `grade_use`는 저장하지 않고 `grade_use(session, result)`로 계산 | 세션 유형과 `verified`에서 도출되는 값이라 저장하면 어긋남. 결과만으로는 세션 유형을 알 수 없어 함수가 세션을 받음 | 저장 필드 |
| 판단 불가 결과도 `reference_only` | 판정이 없어 등급에 쓸 내용이 없음. 시스템 한계가 강사 불이익이 되지 않게 함 (도출 규칙, 정책 확정 아님) | allowed 허용 |
| `confidence`는 `classify/generate`에 필수, `measure`는 선택 | 규칙 계산에는 확신도 개념이 없음 | 모두 필수 |
| pydantic v2, `extra="forbid"`, `frozen=True` | 검증과 JSON 스키마를 같은 정의에서 얻음. 임의 필드 금지 원칙을 코드로 강제 | dataclass |
| `cohort_id`, `institution_id`, `occurrence`는 선택값 | 시뮬레이션·모의수업은 집단이 없을 수 있음. 실제 수업에서 필수로 할지는 이후 | 필수 |
| 모델 정보(`model_id`, `backend`)는 v0 제외 | 로컬/API 비교 eval 설계 때 결정 | 지금 포함 |

## 변경 사항
- `pyproject.toml`(루트, uv 워크스페이스), `uv.lock`
- `packages/core`: `ids`, `enums`, `session`, `event`, `evaluation`, `grading`, `lesson_plan`, `tests/test_schemas.py`
- `docs/02-specs.md` 공통 데이터 형식 절 갱신, `docs/05-coding-rules.md` 확정 항목 추가
- 학습 문서(`docs/learning/260930-schema-v0-design.html`)는 초안 기준이다. 코드와 다른 점: 판단 불가의 `reference_only` 처리, `measure`의 `confidence` 선택, `reason` 필드

## 한계와 주의
- 교차 필드 규칙은 JSON 스키마로 표현되지 않는다. 생성 결과는 모델로 검증해야 한다.
- `verdict` 허용값은 루브릭 확정 후 고정한다. 현재는 `undetermined` 외에는 임의 문자열.
- 퀴즈 결과 확인 없이 사용자 지시로 진행했다.
