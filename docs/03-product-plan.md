## 목적

강사 개인 역량과 관계없이 최소 수업 품질을 보장하고 강사 간 편차를 줄인다.
코어는 사람이 운영하는 표준화 체계(루브릭, 공통 커리큘럼, 모의수업-피드백 프로세스)이고,
AI는 그 체계의 반복 작업을 줄이고 확장 가능하게 만드는 도구다.

## 시스템 관점

강사의 수업 행동을 관찰 가능한 데이터로 바꾸고, 회사 기준(루브릭)과 비교한다.
- AI: 자동 행동 코더 (전사, 분류, 정렬)
- 통계: 지표 산출, 강사 효과와 집단 효과 분리
- 사람: 기준 정의, 최종 판단

## 사용자 흐름 (담당자 요구, 261001 반영)

```
커리큘럼·지도안(구조화) → 수업 가이드 제공 → 모의수업 → 루브릭 평가 → 피드백 → 재훈련(기준 충족까지 반복) → 실제 수업
                                          ├ 일반 모의수업 (음성 녹음 기반)
                                          └ 가상 학생 시뮬레이션 (실시간 상호작용)
```

- **수업 가이드:** 커리큘럼(지도안)을 바탕으로 강사가 이해하기 쉬운 형태로 제공한다. 모션·아바타는 필수가 아니다(슬라이드 + 음성 또는 텍스트로 충분).
- **가상 학생 시뮬레이션:** 강사가 본인이 맡은 차시를 선택해 연습한다. 가상 학생과 실시간으로 상호작용한다.
- **평가 입력 방식 두 가지:** ① 수업 음성 녹음 기반, ② 수업하면서 클릭으로 입력(원본 11장 1단계의 디지털 체크리스트와 연결 가능성).
- **평가는 루브릭 기반이 핵심이다.** 항목별 입력 채널(음성 / 클릭 / 둘 다)은 루브릭에서 정한다.
- **평가의 지위:** 시뮬레이션 결과는 실제 수업 예측력이 검증되기 전까지 참고용이다(`AGENTS.md` §2). 공식 평가는 일반 모의수업 쪽에서 나온다(원본 8장 필수 요건).

## 기능과 초기 범위

| 기능 | 원본 정의 | 초기 구현 범위 |
|---|---|---|
| 1 지도안 검토 | AI 사전 검토 | 지도안 구조화 + 규칙 점검 (진단과 가이드의 기준 데이터) |
| 2 수업 가이드 | AI 시연 영상 제작 | **정적 가이드** (슬라이드 + 음성/텍스트). 지도안 데이터 기반, 커리큘럼팀 검토. 모션·아바타는 범위 밖. 261001 보류 해제 |
| 3-① 일반 모의수업 분석 | 영상·음성 분석 | **음성 기반 진단** (영상 분석은 후순위) |
| 3-② 가상 학생 | 실시간 상호작용 | 차시 선택, 사전 설계 시나리오, 텍스트 턴제 기본. 입력은 상호작용 로그 + 클릭. 결과는 참고용 |
| 4 종합 피드백 | 맞춤형 피드백 | 3의 결과를 루브릭 항목별로 정리, 재훈련 반복 |
| 5 실습 진단 | 실습 데이터 분석 | 이후 단계 (기기 로그 수집 확인 필요) |
| 6 수업 중 힌트 | 실시간 힌트 | 이후 단계 (힌트 라이브러리 선택 방식) |

## 현재 집중 범위 (261001 결정)

**수업 전 구축을 우선한다:** 지도안 구조화 → 수업 가이드 → 모의수업(일반, 가상 학생) → 루브릭 평가 → 피드백.
**나중으로 미룬다:** 멀티모달(영상·표정·제스처 분석), 실제 수업 분석, 수업 중 강사 보조(기능 5·6).
- 스키마는 나중 영역을 수용할 여지만 두고(`session_type`의 `real` 값 예약 등), 상세 설계는 하지 않는다.
- 이 해석("1단계" = 위 흐름)은 담당자 확인 대상이다. 원본 11장의 구축 1단계(평가 기준·데이터 구조화)만을 뜻한다면 가상 학생(11장 2단계)도 뒤로 갈 수 있다.

## MVP (수직 슬라이스)

자율주행 한 차시 기준:
지도안 구조화 → 수업 가이드 → 모의수업(가상 학생 상호작용 또는 음성 업로드) → 루브릭 기반 평가 리포트 → 피드백
(시나리오 3~5개, 텍스트 턴제)

## 확인 필요 (담당자)

- "수업 가이드가 실시간 생성"의 의미: 요청마다 새로 생성인가, 검토된 가이드를 즉시 제공인가 (원본은 사전 제작)
- "실시간 상호작용"이 텍스트 턴제로 충분한가, 음성이 필요한가
- 클릭 입력: 누가 클릭하나 (강사 본인 / 관찰자)
- "녹음 기반 시뮬레이션"의 정확한 의미
- 모의수업 "영상" 기반: 녹화 형태인가, 영상 분석(시선·표정·제스처)까지 필요한가
- 가상 학생 수업을 평가 중심에 둘 때, 초기 결과가 참고용이라는 점에 대한 합의
- 차시 선택: 담당 차시 목록에서 고르는 방식인가, 시나리오를 만들 차시는 몇 개인가
- 가이드 형태: 슬라이드 + 내레이션이면 충분한가
→ [scope-confirmation](todo/scope-confirmation.md)

## 범위 밖 (초기)

가이드의 영상 아바타·모션, 학생 표정·참여도 영상 분석, 여러 가상 학생 동시 실시간 음성, SLM 파인튜닝, 실제 수업 분석, 수업 중 강사 보조 (위 "현재 집중 범위" 참조)

## 선결 조건 (회사에서 받아야 할 것)

- 회사가 원하는 강사 수준 기준 (루브릭 차원·수준·목표선)
- 샘플 지도안, 검토 기준 숫자 (시간 비율 등)
- 모의수업 녹화 + 전문가 평가 (검증용)
- 차시별 흔한 오개념 (강사 경험 기반)
