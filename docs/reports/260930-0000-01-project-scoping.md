## 요약
기획안 V0를 검토하고, 전체 시스템이 아닌 음성 기반 진단 중심의 수직 슬라이스로 초기 범위를 정했다.
AI를 코어가 아닌 표준화 체계의 가속기로 위치시켰다.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 코어는 사람이 운영하는 표준화 체계, AI는 보조 | 검증 안 된 AI가 핵심 약속을 지면 품질 자체가 흔들림 | AI 중심 시스템 |
| 강사 역량 루브릭을 루프의 중심에 둠 | 기준 없이 기능 정의가 불가능 | 기능별 개별 기준 |
| LLM은 분류·서술만, 측정은 규칙 | 할루시네이션 통제, 검증 용이 | LLM 자율 판단 |
| 평가는 강한 하네스, 훈련은 틀 안 유연 | 평가는 불이익과 연결, 훈련은 과통제 시 무용 | 동일 강도 |
| 기능 1은 검토 도구가 아닌 지도안 구조화(기준 데이터) | "GPT에 물어보면 되지 않나"에 답이 안 됨 | 독립 검토 기능 |
| 기능 2 영상 생성 보류 | 학습 가치 대비 비용 최대 | 아바타 영상 |
| 음성 우선, 영상은 후순위 | 평가 가치 대부분이 음성에서 나옴 | 완전 멀티모달 |
| 모노레포, 실행 분리·스키마 공유 | 수업 전(배치)과 수업 중(실시간·오프라인) 요구가 다름 | 저장소 분리 |
| "에이전트 시스템" 명칭 미사용 | 고정 파이프라인 중심 설계와 맞지 않음 | 에이전트는 가상 학생·수업 보조 모듈에만 |
| G-Eval은 통째 도입 X, 단계 명시 + logprob 확신도 라우팅만 | 핵심은 범주 코딩이지 세밀한 점수가 아님 | G-Eval 전면 도입 |
| Whisper 파인튜닝 보류 | VAD + 용어 프롬프트 + 마이크로 먼저 해결 | 즉시 파인튜닝 |
