## 요약
담당자가 구두로 전달한 요구를 원본 기획서와 대조하고, 사용자가 원하는 형태(가이드 → 모의수업 → 루브릭 평가)로 문서를 재구성했다.
원본에 없는 요구(차시 선택, 클릭 입력, 녹음 기반 시뮬레이션)와 해석이 갈리는 부분은 확인 질문으로 남겼다.

## 주요 결정
| 결정 | 이유 | 대안 |
|---|---|---|
| 기능 2 보류 해제, 정적 수업 가이드(슬라이드 + 음성/텍스트)로 재정의 | 담당자가 1단계에 원함. 보류 이유(아바타 영상 비용)가 정적 형태에서는 사라짐. 지도안 구조화 데이터로 생성 가능 | 보류 유지 / 영상 제작 |
| 가이드는 지도안 데이터와 전문가 정의 대응에서만 생성, 커리큘럼팀 검토 | "LLM은 사실의 출처가 아니다" 원칙 | 자유 생성 |
| 가상 학생 시뮬레이션을 흐름에 포함하되 결과는 초기 참고용 | `AGENTS.md` §2, 원본 6·8장 | 공식 평가에 포함 |
| 평가 입력 채널을 루브릭 항목에 표시 (음성 / 클릭 / 둘 다) | 클릭은 ASR 오류와 무관한 신호. 담당자 요구 | 음성만 |
| MVP 흐름: 지도안 → 가이드 → 모의수업 → 루브릭 평가 → 피드백 | 담당자 흐름 + 원본 1장 1~4단계 | 음성 진단 단독 MVP |
| 로컬 모델 우선 방침을 02에 기록, API 전환은 조건부 검토로만 남기고 현재 금지 규칙(`AGENTS.md` §3)은 유지 | 담당자 요구는 "로컬 우선, 나중에 필요하면 API". 미성년자 데이터가 걸린 금지 규칙은 정책 확인과 eval 근거 없이 풀 수 없음 | 금지 규칙 즉시 완화 / API 우선 |
| `services/llm`을 백엔드 교체 가능한 인터페이스로 설계 | 전환 비용을 낮추고 로컬 대 API 비교를 가능하게 함 | 로컬 전용 구현 |
| 수업 전 구축을 우선하고 멀티모달·실제 수업·수업 중 보조는 나중으로 미룸 | 사용자 결정. 담당자 요구 흐름이 수업 전에 집중됨. 스키마는 확장 값만 예약 | 전 영역 병행 |
| 해석이 갈리는 항목은 문서에 "확인 필요"로 표시하고 담당자 답을 받기 전 확정하지 않음 | 추측으로 범위를 정하지 않기 위해 | 임의 해석 |
